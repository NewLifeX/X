# 多语言本地化

NewLife.Core 的异常、日志与界面提示统一支持多语言。内置 31 种语言，英文为源文与兜底；默认跟随当前 UI 语言，缺失翻译自动回退英文。

## 1. 选择语言

| 设置 | 作用 |
|---|---|
| `Setting.Language` | 全局语言设置。留空自动跟随系统；填写受支持语言后固定界面与日志语言。配置加载与保存时自动应用，清空后恢复自动识别 |
| `CultureInfo.CurrentUICulture` | 默认语言来源。`HttpServer` 默认按请求 `Accept-Language` 设置；ASP.NET Core 启用 `RequestLocalization` 时同样按请求变化 |
| `Localization.Culture` | 强制指定异常与常规文本语言；`null` 表示跟随 `CurrentUICulture` |
| `Localization.LogCulture` | 日志与配置注释的语言；`null` 表示跟随 `Culture` |

```csharp
// 全局固定中文（配置项，推荐）
Setting.Current.Language = "zh-CN";
Setting.Current.Save();

// 代码内直接设置（进程级）
Localization.SetLanguage("zh-CN");
Localization.SetLanguage("");      // 回到自动识别

// 启用请求语言识别时，让日志和配置注释保持英文
Localization.LogCulture = new CultureInfo("en-US");
```

- `Localization.GetLanguages()` 返回当前支持的语言清单（内置 + 运行时注册），每项含配置键 `Name`、自称 `NativeName` 与英文名 `EnglishName`；`GetDisplayName()` 给出下拉框文本，如中文界面的 `德语 (Deutsch)`、英文界面的 `Chinese (Simplified) (简体中文)`。旧版别名（`in`/`iw`/`no`/`mo`）自动归一到 `id`/`he`/`nb`/`ro`，不会重复出现在清单里。区域数据未本地化（如英文界面、缺少 ICU 数据）时按英文名显示，可用词表以英文名为键改写。
- `Localization.GetLanguageOptions()` 直接把语言清单转成「语言键 → 显示名称」字典，管理端下拉框一行代码即可绑定；“自动”项由宿主添加，因为它的文本也要随界面语言本地化。
- `Localization.NormalizeCulture(name)` 归一化语言名称，如 `en`→`en-US`、`de-AT`→`de-DE`、`zh-Hant`/`zh-HK`→`zh-TW`、`in`→`id-ID`；不支持的语言返回 `null`。
- `Localization.IsSupported(culture)` 判断某区域是否有可用译文。
- Xml/Ini 配置文件注释会列出全部内置语言码；没有界面时，可直接按配置注释填写 `Language`。
- ASP.NET Core 仍可启用 `RequestLocalization` 做请求级识别；当 `Setting.Language` 非空时，管理端应在请求管道中强制覆盖，保证界面与日志都使用固定语言。
- 语言表在配置加载之后才可用（如插件延迟加载）时，宿主可在插件初始化完成后调用 `Setting.Current.ApplyLanguage()` 重新应用配置语言。

`HttpServer`/`HttpSession` 默认对每个请求按 `Accept-Language` 设置 UI 文化，无需注册中间件：

- 语言优先级：`Setting.Language`/`Localization.Culture`（固定语言）→ `Accept-Language` 中 q 权重最高且受支持的语言 → 服务器当前语言；
- 只修改 `CurrentUICulture`，不影响数字与日期格式；
- 宿主固定语言后，`Accept-Language` 不再生效。

其它 Web 宿主（如自研 HTTP 协议处理）可显式使用 `RequestCultureScope`：

```csharp
using var culture = RequestCultureScope.Create(acceptLanguage);
```

## 2. 在代码中使用

| 场景 | 写法 | 是否需要改调用点 |
|---|---|---|
| 自定义异常 | `throw new XException("Session {0} is closed.", sessionId);` | 否，构造器自动翻译 |
| BCL 异常 | `throw new InvalidOperationException(L.T("Session {0} is closed.", sessionId));` | 是，替换消息 |
| 日志 | `XTrace.WriteLine("Session {0} is closed.", sessionId);` | 否，`Logger.Format` 自动翻译 |
| 手工拼装的日志片段 | `L.TLog("Session {0} is closed.", sessionId);` | 是，改用日志语言入口 |
| 带实例前缀的日志 | `Log?.InfoPrefixed(prefix, format, args)` | 是，改用 ILog 扩展 |
| 自定义 Logger | 重写 `Format` 时调用 `Localization.TranslateForLog(format, args)` | 是，一行 |

- 日志使用**格式字符串 + 参数**，不要用字符串插值（`$"..."`）：插值后模板已展开，无法再按原文查表。
- 模板按**整句**查表，参数本身不会翻译。不要把英文状态词作为 `{n}` 参数塞进模板，否则会得到中英混排；应按语义拆成多条完整英文句子。
- 实例前缀（如 `[Session]`、`LogPrefix`）必须在翻译之后拼接；`InfoPrefixed` / `ErrorPrefixed` / `WritePrefixed` 已按此处理。
- Xml/Ini 配置提供者在保存时按 `Localization.LogCulture ?? Localization.Culture` 翻译 `[Description]`/`[DisplayName]` 注释；两者都未显式设置时输出英文源文，不跟随 `CurrentUICulture`。

## 3. 下游组件接入

在组件项目下新建 `Locales/<culture>.yml`，每行一条：

```yaml
"Session {0} is closed.": "会话 {0} 已关闭。"
```

- 键必须是**英文原文**，且与代码中的模板完全一致；占位符集合必须一致，否则构建失败。
- 英文是源文与兜底，**不需要 `en.yml`**；缺失翻译不报错，运行时回退英文。
- 用 `PackageReference` 引用主包时，`Locales/*.yml` 会自动挂载，通常无需修改 csproj；用 `ProjectReference` 直连源码时需显式声明：

```xml
<ItemGroup>
  <AdditionalFiles Include="Locales\*.yml" />
</ItemGroup>
```

- 应用（可执行程序集）的译文默认覆盖 Core 同名词条，类库默认只补充新词条；类库确需覆盖时：

```xml
<PropertyGroup>
  <NewLifeLocalizationOverwrite>true</NewLifeLocalizationOverwrite>
</PropertyGroup>
```

- 运行时新增语言（插件、租户自定义等，无需重新编译）：

```csharp
Localization.Register(new CultureInfo("th-TH"), thaiTable);
```

## 4. 语言清单与回退

| Culture | 回退映射 |
|---|---|
| `en` | 默认与兜底 |
| `zh-Hans` | `zh-CN` / `zh-SG` → `zh-Hans` |
| `zh-Hant` | `zh-TW` / `zh-HK` / `zh-MO` → `zh-Hant` |
| 其余语言 | 语言子标签相同即命中，如 `de-AT` → `de`、`pt-BR` → `pt`、`es-MX` → `es` |

当前内置 31 种语言：

| 区域 | 语言 |
|---|---|
| 东亚 | `zh-Hans`、`zh-Hant`、`ja`、`ko` |
| 东南亚/南亚 | `vi`、`th`、`id`、`ms`、`hi`、`bn` |
| 中东 | `ar`、`he`、`fa` |
| 欧洲 | `de`、`fr`、`es`、`pt`、`it`、`nl`、`pl`、`cs`、`sv`、`da`、`nb`、`fi`、`el`、`ro`、`hu` |
| 其他 | `ru`、`uk`、`tr` |

新增语言时把 `<culture>.yml` 放入 `NewLife.Core/Locales/` 即可，构建期会校验键集合、占位符与格式说明符。

## 5. 测试注意

- `Localization.Culture` 是进程级全局状态，并行用例会互相干扰；改写它的测试应归入串行集合（本仓使用 `[Collection("GlobalState")]`）。
- 库测试优先断言异常类型、错误码或行为，不要依赖具体译文；必须断言文案时，显式设置语言。
- CI 的 `CurrentUICulture` 常为 en 或 invariant，断言中文会失败；`InvariantGlobalization=true` 下自动回退英文。
