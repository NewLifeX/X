# 多语言本地化

NewLife.Core 的异常与日志共享一套**编译期生成**的多语言表。默认跟随当前上下文语言，缺翻译自动回退英文；不依赖 resx 与卫星程序集，单 DLL、原生支持 AOT。

## 1. 语言选择

| 设置 | 作用 |
|---|---|
| `CultureInfo.CurrentUICulture` | 默认语言来源。ASP.NET Core 启用 `RequestLocalization` 时按请求变化 |
| `Localization.Culture` | 强制指定异常与常规文本语言；`null` 表示跟随 `CurrentUICulture` |
| `Localization.LogCulture` | 单独固定日志语言；`null` 表示跟随 `Culture` / `CurrentUICulture` |

```csharp
// 全站中文
Localization.Culture = new CultureInfo("zh-CN");

// 启用请求语言识别时，让日志保持英文
Localization.LogCulture = new CultureInfo("en-US");
```

## 2. 使用

### 异常

```csharp
// XException 构造器自动翻译，调用点无需改动
throw new XException("Session {0} is closed.", sessionId);

// 其它异常类型显式翻译
throw new InvalidOperationException(Localization.Translate("Session {0} is closed.", sessionId));
```

### 日志

```csharp
// Logger.Format 统一翻译，调用点无需改动
XTrace.WriteLine("Session {0} is closed.", sessionId);
```

> 日志使用**格式字符串 + 参数**，不要用字符串插值（`$"..."`）。插值后模板已展开，无法再按原文查表。

## 3. 新增内置语言

在 `NewLife.Core/Locales/` 新增 `<culture>.yml`，每行一条：

```yaml
"Session {0} is closed.": "会话 {0} 已关闭。"
```

规则：

- 键必须是**英文原文**，且与代码中的模板完全一致；
- 占位符集合（`{0}`、`{1}`…）必须与英文一致，否则**编译失败**；
- 同一文件内键重复、语法错误同样编译失败；
- 缺失翻译不报错，运行期回退英文；
- 新增键必须**同步补进全部语言文件**，否则 `check-locales.ps1` 报"缺少键"。

语言文件由随 `NewLife.Core` 主包分发的源生成器在编译期生成为静态字典，生成物不随包分发。

### 3.1 覆盖范围与校验

**纳入词表**（运行时可见的消息）：异常消息、日志、控制台输出、界面提示、埋点标签。

**不纳入词表**（元数据/文档）：`[Description]`、`[DisplayName]`、`[Obsolete]`、`[RequiresDynamicCode]` 等特性文本，以及 XML 文档注释——它们不经过查表路径，需要本地化时由管理端（如 Cube）另行处理。

两个守门脚本在 `run-tests.ps1` 与 CI 中执行：

| 脚本 | 校验内容 |
|---|---|
| `check-english-exceptions.ps1` | 异常 / 日志 / 控制台 / 界面提示 / 埋点标签中的运行时消息不得含中文 |
| `check-locales.ps1` | 各语言键集合与 `zh-Hans` 一致、占位符与格式说明符一致、无孤儿键（源码中已不存在的键） |

## 4. 下游组件接入

### 4.1 声明语言文件（推荐）

源生成器已随 `NewLife.Core` 主包以分析器形式分发，下游**无需额外引用生成器包**，只需声明语言文件：

```xml
<ItemGroup>
  <AdditionalFiles Include="Locales\*.yml" />
  <ProjectReference Include="..\NewLife.Core\NewLife.Core.csproj" />
</ItemGroup>
```

在组件项目下新建 `Locales/<culture>.yml`（格式与 Core 相同）。生成器会：

- 编译期校验占位符、格式说明符、重复键与语法；
- 生成 `LocalizationTable`，并通过 `[ModuleInitializer]` **自动注册**到 `Localization`；
- 生成内部 `L` 快捷入口，组件内可直接写 `throw new InvalidOperationException(L.T("English template", args))`。`L` 为 `internal`，不进公共 API；若组件自身已定义 `NewLife.L`，生成器自动跳过，避免类型冲突。
- 组件确实需要自己定义 `L` 又不希望生成时，可设 MSBuild 属性关闭：`<NewLifeLocalizationGenerateL>false</NewLifeLocalizationGenerateL>`。

> 生成器只处理 `Locales/` 目录下的 `.yml`，其他位置的 yml 不会被读取。旧框架没有 `ModuleInitializerAttribute` 时，生成器会补一个内部定义，行为一致。
>
> **本地源码联调**：分析器随 NuGet 主包分发，`PackageReference` 引用 `NewLife.Core` 时自动生效；若下游用 `ProjectReference` 直连 Core 源码，需额外把生成器项目作为分析器引入：`<ProjectReference Include="..\NewLife.Core\NewLife.Core.SourceGenerator\NewLife.Core.SourceGenerator.csproj" OutputItemType="Analyzer" ReferenceOutputAssembly="false" />`。
>
> **回归用例**：`XUnitTest.Core` 自带 `Locales/ta.yml`，等价于一个下游组件，用 `DownstreamLocalizationTests` 覆盖"声明 yml → 生成表 → 模块初始化自动注册 → `Localization.Translate` / `L.T` 生效 → 未注册语言回退英文"整条链路。

### 4.2 异常与日志

| 场景 | 写法 | 是否需要改调用点 |
|---|---|---|
| 自定义异常 | `throw new XException("English template", args)` | 否，构造器自动翻译 |
| BCL 异常 | `throw new InvalidOperationException(L.T("English template", args))` | 是，替换消息 |
| 日志 | `XTrace.WriteLine("English template {0}", arg)` | 否，`Logger.Format` 自动翻译 |
| 自定义 Logger | 重写 `Format` 时调用 `Localization.TranslateForLog(format, args)` | 是，一行 |

### 4.3 覆盖 Core 译文

默认自动注册使用 `overwrite: false`：**Core 已有译文优先**，下游只补充新 key。

需要改写 Core 文案时，在启动阶段显式覆盖：

```csharp
Localization.Register(new CultureInfo("zh-Hans"), table, overwrite: true);
```

### 4.4 同一英文模板冲突

- Core 与下游使用同一英文原文：默认共享 Core 译文；`overwrite: true` 时下游覆盖。
- 两个下游组件使用同一英文原文且都覆盖：**后注册者生效**（由启动顺序决定）。
- 同一句话在不同语境需要不同译法：让模板措辞不同，不要依赖覆盖。

### 4.5 运行时新增语言（不引用生成器）

```csharp
Localization.Register(new CultureInfo("th-TH"), thaiTable);
```

适用于插件、租户自定义语言等场景，不需要重新编译。
## 5. 语言清单与回退

| Culture | 回退映射 |
|---|---|
| `en` | 默认与兜底 |
| `zh-Hans` | `zh-CN` / `zh-SG` → `zh-Hans` |
| `zh-Hant` | `zh-TW` / `zh-HK` / `zh-MO` → `zh-Hant` |
| 其余语言 | 语言子标签相同即命中，如 `de-AT` → `de`、`pt-BR` → `pt`、`es-MX` → `es` |

当前仓库内置 31 种语言（每种 267 条运行时消息，英文为兜底）：

| 区域 | 语言 |
|---|---|
| 东亚 | `zh-Hans`、`zh-Hant`、`ja`、`ko` |
| 东南亚/南亚 | `vi`、`th`、`id`、`ms`、`hi`、`bn` |
| 中东 | `ar`、`he`、`fa` |
| 欧洲 | `de`、`fr`、`es`、`pt`、`it`、`nl`、`pl`、`cs`、`sv`、`da`、`nb`、`fi`、`el`、`ro`、`hu` |
| 其他 | `ru`、`uk`、`tr` |

其余语言按需补充，缺失自动回退英文。

新增语言时把 `<culture>.yml` 放入 `NewLife.Core/Locales/` 即可，构建脚本与 CI 会用 `check-locales.ps1` 校验键集合、占位符与格式说明符。

## 6. AOT 与包体

- 语言表是编译期生成的**静态字典 + switch**，无反射、无 `ResourceManager`、无 manifest resource 读取；
- 不引入运行时 NuGet 依赖；
- 每语言每 TFM 约 43 KB（实测 31 种语言使 net10.0 DLL 从 1,295 KB 增至 2,380 KB，nupkg 从 10.3 MB 增至 11.6 MB）；
- `InvariantGlobalization=true` 时 `CurrentUICulture` 为 invariant，自动回退英文。

## 7. 为什么不用 resx

- resx 默认产出**卫星程序集**（每语言 × 每 TFM 一个 DLL），与"单 DLL"目标冲突；
- 关闭卫星后，`ResourceManager` 默认不会从主程序集解析非中性文化，需要自写 `ResourceSet` 加载；
- 资源查找存在裁剪告警与 `MissingManifestResourceException` 风险；
- XML 噪音大、合并冲突多，翻译协作体验差。

resx 仍然适合**应用层**的 `IStringLocalizer`，与库级多语言是两种不同场景。
