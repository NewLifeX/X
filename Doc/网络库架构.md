# 网络库架构

> 适用范围：NewLife.Core 的 `NewLife.Net`、`NewLife.Messaging`、`NewLife.Data`（数据包部分）与 `NewLife.Http`（服务端）。
> 目标形态：简单架构覆盖 80% 日常场景，剩余 20% 通过明确的扩展点留给下游。
> 配套专题：《数据包IPacket》《数据管道Pipe》《数据包编码器PacketCodec》《网络缓冲所有权架构》《高级二进制序列化》。

## 1. 分层与数据通路

```
应用层      NetServer / NetSession / NetClient
            ↑ 消息与事件
处理器层    Pipeline（Handler 链：Standard / LengthField / Split / Json / WebSocket）
            ↑ 帧
帧引擎      PacketCodec（同步兼容面）      |  PacketFramer（定界泵）
            ↑ 字节流
缓冲层      Pipe（窗口 + 背压）      |  每轮拥有句柄（SessionBase 轮末裁决）
            ↑
传输层      SessionBase / TcpSession / TcpServer / UdpServer / UdpSession
            ↑
接入面      Socket（内置监听与连接）  |  外部 Socket 接管（TcpSession / TcpServer.Attach）
```

**接收数据流（简）**

1. Socket 读回调进入 `SessionBase.ProcessEvent`：本轮数据包装为拥有句柄（`OwnerPacket`），轮末按引用计数裁决——`RefCount==1` 时 `Detach` 复用缓冲，否则归还换新（零 Rent/Return 快路径）。
2. 连接型会话（`TcpSession`）把本轮数据追加进数据管道（`Pipe`，有界背压），其余直接进入传统处理器链。
3. 拆帧定界：管道路径由 `PacketFramer` 泵出完整帧；传统路径由 `PacketCodec` 同步拆帧。
4. 消息回流到会话：`Received` 事件 → `NetSession` → 可选的 `INetHandler`（如 `HttpSession`）→ `NetServer.Received`。

**接收模式（二选一）**：打开前设置 `AutoReceive`（`SessionBase`，默认 true）——true 自动启动接收环走事件推送（接收环运行期间 `Receive/ReceiveAsync` 抛出异常）；false 只允许拉取直读。两模式互斥；拉取模式下可调用无参 `ReceiveAsync()` 手动转事件模式（单向，不回退）。WebSocket 握手发生在打开过程的接收环启动之前，直读天然合法。

**发送数据流**：`Send` → 管道处理器逆序编码（后→前）→ Socket（或 SSL `_Stream`）→ 网卡。

## 2. 80% 黄金用法

### 2.1 服务端 + 编解码

```csharp
class MyServer : NetServer<MySession> { }

class MySession : NetSession<MyServer>
{
    protected override void OnReceive(ReceivedEventArgs e)
    {
        var pk = e.Packet;   // 当前指令的数据帧
        if (pk == null || pk.Length == 0) return;
        Send(pk);            // 回发
    }
}

var server = new MyServer { Port = 0 };
server.Add<StandardCodec>();      // 或 LengthFieldCodec / SplitDataCodec / 自定义编解码器
server.Start();
```

- 内置编解码器：`StandardCodec`（新生命标准封包）、`LengthFieldCodec`（长度字段，MQTT 风格）、`SplitDataCodec`（分隔符）、`JsonCodec`（JSON 文本）。
- 也可以不定义会话子类，直接 `server.Received += ...` 集中处理。

### 2.2 客户端

```csharp
var client = new NetUri("tcp://127.0.0.1:1234").CreateRemote();
client.Add<StandardCodec>();
client.Open();

client.Send("Hello".GetBytes());
```

- 请求-响应：`SendMessageAsync`，由 `StandardCodec`/`MessageCodec<T>` 的匹配队列完成应答配对。
- 断线重连等应用级能力可使用 `NetClient`。
- 纯拉取客户端（Modbus/短连接请求-响应风格）：打开前设 `client.AutoReceive = false`，用 `Receive()/ReceiveAsync(ct)` 直读 Socket。

### 2.3 自定义协议

- 继承 `MessageCodec<T>`，实现 `Encode / Decode / IsMatch`；参考 `Net/Handlers/StandardCodec.cs` 与 `LengthFieldCodec.cs`。
- 拆帧器按会话懒建并存入 `ss["Codec"]`（`IExtend` 键，处理器实例跨会话共享，禁止放实例字段），`Close` 时归还。
- 帧长定界统一用 `GetFrameLength`（序列委托，窗口为帧首起的只读序列，帧头跨段自然可读）；消息协议直接绑定 `Message.TryParse`（`buffer => parser.TryParse(buffer, out _)`），裸协议给出定界逻辑。

### 2.4 流式协议（新协议推荐）

- 连接型会话（`TcpSession`，接口 `IStreamSession`）的 `Pipe` 懒建：`Pipe` 承载字节流窗口与背压，`PacketFramer` 定界取帧（同步 `Pump` / 异步 `ReadFrameAsync`，支持头部先行 + body 限长读取）。
- 出站方向：`TcpSession.SendPipe` 懒建（创建后 `Send` 系列单出口入管道；发送泵为内部组件 `SendPump`，批量送出），写侧 `FlushAsync(waitForResume:true)` 获得发送回压，关闭时先排空再关连接；`TcpSession.SendAsync(Stream)` 流式发送（分块零拷贝入管道），大文件不整段驻留；消息协议头 + 流式体：`Message.BuildHeaderPacket(payloadLength)` 声明长度后接 `SendAsync(Stream)`（旧名 `ToHeaderPacket` 保留为兼容桥），与接收侧 `TryParseHeader` + `Body` 对称。
- 传输层大负载：HTTP 响应体 `HttpResponse.BodyStream`（可寻址流→Content-Length，未知长度→`Transfer-Encoding: chunked`；静态文件/嵌入资源已接入，大文件不物化）；WebSocket 大帧 `WebSocketMessage.BuildHeaderPacket`（服务端方向无掩码）配合 `SendAsync(Stream)`。
- 细节与示例见《数据管道Pipe》。

### 2.5 消息帧契约（IFrameMessage）

- 帧消息统一契约 `IFrameMessage`：`TryParseHeader`（头先行解析，不足不消费）/`ReadFrame`（整帧解析）/`Build`（整帧构建）/`BuildHeaderPacket`（头 + 流式体）/`Body`（内存视图或限长流式读取器）/`SetBody`。命名对齐主流 HTTP 栈（`ReadFrame`/`Build` 对应 Kestrel `HttpRequest/HttpResponse` 读写语义）。
- 消息类别单一枚举 `MessageKind`（Request/OneWay/Reply/Error，对应 SRMP 头高 2 位）；旧 `Reply/Error/OneWay` 布尔保留为桥接。解析/构造路径一律**一次性写 `Kind`**：三个布尔桥接 setter 的 false 分支映射不同，顺序赋值会互相覆盖。
- `Build` 为转移语义：构建成功后消息不再持有体（清空 `Payload`），调用方 Dispose 返回包即归还；`SetBody(null)` 表示所有权转移，不归还。
- 历史兼容：`IMessage` 保持原样冻结（生态二进制实现面）；旧名 `Read/ToPacket/TryParse` 保留为桥接，新代码面向 `IFrameMessage`。`WebSocketMessage` 不承载请求-响应语义，独立实现帧契约（不继承消息基类）；升级本库后引用 WS 消息类型的项目需重新编译（源码级成员形态不变）。

## 3. 20% 扩展点目录

| 深度 | 扩展方式 | 关键类型 |
|:----:|----------|----------|
| 1 | 自定义编解码器 | `IPipelineHandler` / `Handler` / `MessageCodec<T>`；`server.Add<T>()` 注册 |
| 2 | 自定义会话 | `NetServer<TSession>` / `NetSession<TServer>`；override `OnConnected / OnDisconnected / OnReceive` |
| 3 | 会话级业务处理器 | `INetHandler`（`NetServer.CreateHandler` 返回，如 HttpServer → HttpSession） |
| 4 | 请求响应匹配策略 | `IMatchQueue`（`DefaultMatchQueue.Add / Match` 可重载） |
| 5 | 接管外部 Socket | 客户端 `new TcpSession(socket)` + `Open()`（跳过连接直接收发）；服务端 `TcpServer.Attach(socket)`；NetServer 场景可从 `netServer.Servers` 取 `TcpServer` 后 Attach |
| 6 | 自定义传输 | `ITransport`（帧传输抽象，串口/自定义链路接入）；`NetServer.AttachServer(ISocketServer)` 挂接自定义服务器 |
| 7 | 数据管道回调 | `TcpSession.CreatePipe` 重载（`IStreamSession`）；`PacketFramer.Pump / ReadFrameAsync` |

## 4. 交付上下文契约（数据可带上传输对象）

- 协议层/处理器：`IHandlerContext.Owner` 与 `NetHandlerContext.Session` 均指向会话对象（`ISocketRemote`）；裸 Socket 经 `ISocket.Client` 获取。
- 应用层：`NetSession.Session`（`ISocketSession`）→ `ISocket.Client` 获取底层 Socket；`Remote/Local` 等地址信息同源。
- 接管场景：`TcpSession(Socket)` / `TcpServer.Attach(Socket)` 接管后，会话的 `Client` 即为调用方传入的 Socket；客户端接管会话的 `ISocketSession.Server` 为空。
- 原则：不新增平行的数据上下文对象；所有投递入口（`FireRead`、帧泵回调、流式消息）都在处理器上下文作用域内执行，可回溯到会话与传输对象。

## 5. 双帧引擎定位（选型规则）

| 场景 | 引擎 |
|------|------|
| 新协议；流式、大帧、双向流 | `Pipe` + `PacketFramer`（主干） |
| 存量粘包式协议；同步处理器内拆帧 | `PacketCodec`（兼容面，新协议不再新增使用） |
| 旧二进制（MQTT/RocketMQ/JT1078 等按 v11 编译） | 三参 `Slice`、`Rent/Return` 等 Obsolete 壳（勿删，见《数据包IPacket》）；`PacketCodec.GetLength2` 已随本次帧引擎重构删除（旧双委托统一为序列版 `GetFrameLength`） |

**评估结论（2026-09-16）**：不做 PacketCodec 单一引擎外观化。原因：① `Pipe.Writer.Append` 要求所有权转移（视图/借阅输入必须拷贝），会改变“视图输入返回借阅视图”的既有契约；② 帧首连续保证曾与管道不对称（2026-09-16 已随 PacketCodec 简化移除：双引擎统一为链感知委托跨段拼读），不再构成外观化障碍；③ 定向套件（S1~S6）与零拷贝基准（借用单轮 ~90ns、拥有句柄两轮 ~5.8µs）已把链模型语义固化为契约，外观化无法同时通过语义与基准验证门。概念统一改经共享帧长委托形态达成：双引擎统一序列委托 `GetFrameLength`，消息协议直接绑定 `Message.TryParse`。删除评估：旧双委托（`GetLength` IPacket 版 / `GetLength2` span 版）已随本次重构删除（按用户要求放弃旧二进制兼容面）。

## 6. 概念处置表（v12 收敛）

| 抽象 | 处置 | 状态 |
|------|------|:----:|
| `SessionBase` | 保留为 TCP/UDP 共用报文核心；字节流管道与单出口发送队列下放 `TcpSession` | ✅ 2026-09-17 |

## 7. 兼容纪律（改动本库前必读）

- 公开 API 的删除、改名、返回类型收窄都会断开旧二进制（CLR 成员引用绑定包含返回类型）；优先新增成员。
- `[Obsolete]` 壳（三参 `Slice`、`OwnerPacket.Free`、`GetLength2`、`Rent/Return`）服务于旧二进制；删除前必须扫生态源码与已发布二进制。
- 变更公开面后的默认门禁：全 18 TFM 编译（含 net45）+ 全量测试 + 生态扫描（`C:\X` 下游仓库与 NuGet 缓存 `newlife.*` 产物）。

## 附录 A：UdpSession 收敛评估（2026-09-16，仅评估）

**现状**：`UdpSession` 不继承 `SessionBase`，独立实现发送（×4）/接收/日志/错误处理；与 `UdpServer` 共享同一 Socket，按远端地址懒建，空包结束会话；`ITransport` 的 `Open/Close` 为桩实现。

**收敛候选**：① 继承 `SessionBase`——基类接收环与每轮拥有句柄模型围绕独占 Socket 设计，UDP 是共享 Socket 按远端分片，直接继承需给基类增加传输抽象层，波及 UdpServer 热路径；② 抽取共享的发送/日志/错误处理助手——范围小，但只消除重复样板，不解决双模型差异。

**结论**：暂不实施。收益（减少重复代码）小于风险（触及 UDP 接收热路径与 2500+ 用例回归面）；未来如实施，优先候选 ② 渐进收敛。
