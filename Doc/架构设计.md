# NewLife.Core 架构设计

> 版本：v12 | 日期：2026-10-07 | 从代码结构逆向整理

本文档描述 NewLife.Core 核心库的架构设计。需求定义见[需求文档](需求文档.md)，功能追踪见[功能清单](功能清单.md)。

## 1. 项目分层

NewLife.Core 采用**单项目 + 目录命名空间**的轻量分层架构，不拆分多项目（符合 NewLife 从两层起步的理念）。

```
NewLife.Core/
├── Common/          # 根命名空间 NewLife.*（基础类型）
├── Extension/       # NewLife.* 扩展方法
├── Event/           # NewLife.* 事件与弱引用委托
├── Exceptions/      # NewLife.* 异常类型
├── Stub/            # 兼容性填充（低版本 .NET 缺失类型）
├── Collections/     # NewLife.Collections 集合与池化
├── Caching/         # NewLife.Caching 缓存系统
├── Configuration/   # NewLife.Configuration 配置系统
├── Data/            # NewLife.Data 数据结构与数据管道
├── Log/             # NewLife.Log 日志与追踪
├── Model/           # NewLife.Model 应用框架
├── Reflection/      # NewLife.Reflection 反射扩展
├── Net/             # NewLife.Net 网络库
├── Http/            # NewLife.Http HTTP 组件
├── Remoting/        # NewLife.Remoting RPC 框架
├── Serialization/   # NewLife.Serialization 序列化
│   ├── Json/        # JSON 序列化子模块
│   └── Xml/         # XML 序列化子模块
├── Security/        # NewLife.Security 安全加密
├── Threading/       # NewLife.Threading 定时调度
├── Messaging/       # NewLife.Messaging 消息、帧泵与编解码器
├── Web/             # NewLife.Web Web 工具
├── IO/              # NewLife.IO 文件与存储
├── Compression/     # NewLife.Compression 压缩归档
├── Algorithms/      # NewLife.Algorithms 数据算法
├── Buffers/         # NewLife.Buffers 高性能缓冲区
├── Xml/             # NewLife.Xml XML 配置
├── Windows/         # NewLife.Windows Windows 特定
├── Setting.cs       # 核心配置 Setting
└── NewLife.Core.csproj  # 多目标框架：net45~net10.0
```

## 3. 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 项目结构 | 单项目 + 目录分区 | 符合两层起步理念，减少维护成本 |
| 命名空间 | 每目录一个独立命名空间 | 清晰模块边界，便于按需引用 |
| 多目标框架 | net45~net10.0（18 个 TFM，含 6 个 -windows 变体） | 最大兼容性，Stub 目录填充缺失类型 |
| 日志设计 | `ILog` 接口 + `XTrace` 静态门面 | 兼顾 DI 注入和静态便捷访问 |
| 缓存设计 | `ICache` 统一接口 | 内存/Redis/自定义实现可互换 |
| 序列化 | 自研高性能实现 | 避免依赖第三方库，控制性能 |
| 网络库 | 全异步 Socket | 单机实测 2266 万 tps |
| 数据包 | `IPacket` 零拷贝切片 | 网络层核心性能优化点 |
| 数据包所有权 | 引用计数共享切片（`Slice` 各自释放、引用归零归还；接收轮末按轮句柄 `RefCount` 裁决复用或换新） | 跨轮共享安全 + 零拷贝，消除借用视图悬垂与拷贝代偿 |
| 编解码 | `MessagePump` 帧泵 + 无状态 `IMessageCodec` 单栈（头部到齐即交付、大帧流式体） | 整删 `PacketCodec` 与 Handlers 处理器族；协议实例可跨连接共享，统一整帧与流式两态 |
| 生态兼容 | 旧版兼容壳按需保留：三参 `Slice` 保留 `[Obsolete]` 壳（二进制兼容面，语义已统一为引用计数共享）；`Free`/`Rent`/`Return` 等壳删除 | 大版本破坏性变更下按下游迁移成本逐项取舍兼容面 |
| 协议契约扩展 | `IMessageCodec` 不新增成员、不改变继承关系 | 该接口是生态实现最多的契约，加成员或加继承会使全部外部实现者 `TypeLoadException`；能力差异经 `IMessageMatcher`（配对）、`IMessageCodecDecorator`（装饰器逐层解包）与明确的 `NotSupportedException` 表达 |
| 帧交付编排 | TCP 与 UDP 共享匹配语义（`IMatchQueue` + 共享 `ResponseMatcher`），交付编排各自实现，不抽统一调度器 | 两种传输形态的循环差异大，抽取会把消息泵循环与数据报循环硬编在一起，收益仅为代码组织 |
| 会话状态权威 | 六处状态收敛为「一个终态（`Disposed`）+ 一个存在性（`Sessions`）+ 若干派生量」，以文档 + XML 注释 + 契约用例固化，不合并结构 | `ISocketClient.Active` 为公开可写属性、`ISocketServer.Sessions` 形态被 `HttpServer` 与生态直接消费，收窄或合并会断旧二进制 |
| 会话类型模型 | `UdpSession` 不继承 `SessionBase`；`IStreamSession` 只建模管道，不含流式发送能力 | 基类接收环围绕独占 Socket 设计，UDP 为共享 Socket 按远端分片；给 `IStreamSession` 加发送成员会断实现者 |
| UDP 会话级拉取收口 | `UdpSession.Receive/ReceiveAsync` 不再直读共享 Socket，直接抛 `NotSupportedException` 并指引替代入口（`UdpServer` 拉取需 `AutoReceive=false`、`NetClient`、`Received` 事件）；拉取统一归 `UdpServer`（`SessionBase`）；会话级 `Timeout` 同步收口（不再写共享 Socket 的 `ReceiveTimeout`，仅为 `ITransport` 契约保留） | 服务器 Socket 为多会话共享：按会话过滤拉取会静默丢弃其他会话的数据报，且与服务器级拉取/接收环争抢同一 Socket；生态与仓储扫描无会话级拉取调用点。被否方案：委派 `Server.Receive()` 会把别人的数据报交给调用方；保留带过滤的拉取等于保留已知逻辑错误 |
| WebSocket 帧循环 | 服务端与客户端保持双帧循环，不合并 | 合并属组织性重构、无行为收益 |
| HTTP 派发 | 处理器契约异步（`Task ProcessRequestAsync`），会话级派发保持同步 | 会话级异步派发需一并解决响应保序、请求体跨轮所有权与低版本线程本地上下文传递 |
| 网络栈已知容忍项 | `Upgrade._Client` 不补释放、`SendAllAsync` 逐会话 `Task.Run`、`NetHelper.ParseEndPoint` 解析失败抛异常、WebSocket 发送不分片（大帧整帧构建） | 均为权衡后有意保留的现状，理由见各类型 XML 注释 |
| TinyHttpClient 定位 | 只服务内网高吞吐的 HTTP/1.1 基础子集：http/https、KeepAlive、定长体与分块传输、整次请求超时、重定向；其余（1xx、非 chunked 传输编码、压缩、Cookie、认证、代理、连接池、RPC）一律显式抛异常，不静默降级 | 生态 60+ 仓库与 Core 生产代码均无调用，唯一使用者是自身测试；按通用客户端标准补协议覆盖只增复杂度。RPC 归 `ApiHttpClient`，通用 HTTP 归 `System.Net.Http.HttpClient`（全部 TFM 均可用）；分块解码与 `HttpSession` 共用 `ChunkedDecoder` |
| IoC | `ObjectContainer` 自研 | 轻量级，兼容 `IServiceProvider` |
| 负载均衡 | 故障转移/加权轮询/竞速 | 覆盖不同场景需求 |
| Remoting 生态迁移 | 拆端口方案：SRMP 保留 `Port`，HTTP/WebSocket 独立 `HttpPort`（默认 `Port + 1`） | 对齐单一协议栈模型，各协议各走独立端口；来源：NewLife.Remoting ChangeLog（2026-10-05） |
| AOT 兼容 | 主链路以泛型/Type 入口保留注解 + 源生成器静态表承接；动态能力（插件/脚本/DLR/表达式编译）声明性排除 | 支撑 NativeAOT 原生发布（25 场景实测 + CI 防回归），边界见《AOT兼容性分析》 |

## 5. 编码约定

见项目根目录 `.editorconfig` 和 `global.json`。

| 约定 | 说明 |
|------|------|
| 类型名 | .NET 正式名：`String`/`Int32`/`Boolean`（非 `string`/`int`/`bool`） |
| Nullable | 全局启用 `<Nullable>enable</Nullable>` |
| 语言版本 | `<LangVersion>latest</LangVersion>`（C# 14） |
| 文档注释 | XML 注释所有 public/protected 成员，`<summary>` 同行闭合 |
| 签名 | 强命名（`newlife.snk`） |
