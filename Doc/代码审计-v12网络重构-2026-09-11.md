## 三、发现明细

### P0-1 半回退："事件认领即停"三处不一致

- 代码/测试/《网络缓冲所有权架构.md》= d67 之前版本（无认领即停）；
- 但《数据包编码器PacketCodec.md》（d67 版本）有 3 处描述"事件内 Take 认领则本条不再匹配"，并引用不存在的 §6；
- 下游 `NewLife.Remoting/ApiClient.cs` 注释按 d67 语义规划（"偷走后本条不再匹配"）。
- 需二选一：恢复 d67 语义（取回上述 3 个文件），或正式放弃并同步修改 PacketCodec.md 与 Remoting 注释。
- 注：不恢复时，事件内 Take 与响应匹配赠送之间存在同线程可达的克隆兜底竞态（d67 原本要解决的问题）。

### P0-2 WebSocket 大帧（>8KB）被静默丢弃【实测确认；本重构暴露】

- 机理：新 PacketCodec 对跨轮大帧产出链式帧（零拷贝）；`WebSocketMessage.Read` 的预检 `reader.Available < need` 在链式入参时（SpanReader 转流式物化，Available 只算当前 8KB 块）误判"数据未到齐"→ 返回 false → `WebSocketCodec` 丢弃该帧。
- 复现数据（临时工程 `%TEMP%\v12-ws-check`）：
  - 链式 60KB（按 8KB 分段）→ **Read=False（丢弃）**
  - 单段 60KB → Read=True
  - 链式 5KB → Read=True；链式 8KB 未掩码（4KB 分段）→ Read=True
- 默认接收缓冲 `SocketSetting.BufferSize = 8 * 1024`；即默认配置下 WS 消息 >8KB 且跨接收轮到达时会被丢弃（双向均可能，掩码与否无关——掩码实测走 EnsureSpace 物化路径，本身正常）。
- 旧实现慢路径把帧拷贝为单段，不触发该问题；属"链式帧使既有预检缺陷可达"。
- 修复方向：让预检使用"剩余总量"语义（SpanReader 增加总量/或该处改用可失败读取）；同时补一条"链式大帧 WS 往返"回归测试。

### P1 `OwnerPacket.Slice` 链式跳过首节点不归还【实测确认】

- 场景：帧头跨段且首段过短，`Slice(offset,...)` 递归跳过首节点时未释放该节点所有权。
- 实测：`s1.Slice(6, -1, true)` 后 `s1._hasOwner=True`（期望 False）——池化数组漏归还（GC 可回收，非永久泄漏，但违背零 GC 目标）。
- 建议：在 `remainInCurrent <= 0` 分支中，对 `transferOwner` 的跳过节点归还其缓冲（注意勿动 `Next`）。
- 注：该文件（`Data/IPacket.cs`）不在本次未提交改动内，属顺带发现。

### P2 其他（低风险）

- `JsonCodec` 消息归一用 `pk.GetMemory()` 仅取链首段（实测：链式 7 字节返回 3 字节）；旧 `ToStr()` 为链感知。链式输入会截断。
- `SplitDataCodec.Decode` 输出类型 `IPacket → Memory<Byte>`：行为变化，仓库内仅一处测试使用，但属对外隐性破坏，建议在 ChangeLog 标注。
- `DefaultMessage.Read` 每消息一次 ≤8 字节数组分配（`SpanReader.ReadBytes`），与零 GC 目标打折。
- XML 警告 3 条：2 条由半回退引入（`MessageCodec.Decode` 的 `<param name="data">` 与签名 `pk` 不符）；1 条 cref 解析失败（`DefaultMessage`）。
- 无等待方时 `MatchResponse` 的拥有负载被丢弃（存量问题，非本次引入）。

## 四、认领即停语义对比

| 维度 | A. 认领即停（d67） | B. 认领后仍匹配（当前 405 版本） |
|---|---|---|
| 事件内 `e.Take()` 后，await 方结果 | 超时取消（本题不再响应匹配） | 仍收到**克隆副本** |
| 事件方结果 | 拥有整块缓冲 | 拥有整块缓冲 |
| 内存成本 | 零克隆 | 每次多一次 Clone 拷贝 |
| 竞态风险 | 无（匹配不再触碰该缓冲） | 事件方同步归还/复用时，克隆可能读取已归还缓冲（窗口小但真实） |
| 语义 | "先到者得"、一包不两送，边界清晰 | "双份送达"，可能引起业务重复处理歧义 |
| 与现有文档/跨仓计划 | 与 PacketCodec.md、Remoting 迁移注释一致 | 与 PacketCodec.md、Remoting 注释冲突（需同步修改） |
| 对监控型订阅者的友好度 | 误用 Take 会打断请求-响应（等待方超时，排查较难） | 更宽容，但引入上述竞态 |

- 仓内 `Take` 调用点扫描：仅 `PacketCodec`（残片整块偷走）、`MessageCodec.MatchResponse`（响应赠送）+ 测试；**无业务事件处理器调用 Take**；Remoting 尚未使用。
- 倾向建议：恢复 A（语义干净、零拷贝、无竞态、与外围一致），并在文档中继续强调"事件处理器只读，需要独占才 Take"。

## 2026-09-11 第二轮复核与修复（补记）

围绕“处理器实例跨会话共享、会话态必须挂会话”与“链式帧彻底零物化”两条线深挖，修复四项：

- **A. WebSocketCodec 粘包编码器改为按会话隔离【真 bug，已实证】**：原实现用处理器实例字段 `_packetCodec`，而服务器会话直接共享同一管道/处理器实例 → 多客户端并发时跨会话串包、上下文竞态，且单个会话关闭会归还共享编码器。改为存会话 `IExtend` 独立键 `ss["WebSocketCodec"]`（与消息族编码器的 `ss["Codec"]` 区分，允许级联），`Close` 归还本会话编码器。
  - 新增 `WebSocketCodecSessionTests`（3 客户端 × 6 轮 × 60KB 并发回显）：修复前实测 3/3 串包（回显 86/31 字节、内容错位），修复后全绿。
  - 顺带：`StandardCodec`/`LengthFieldCodec`/`SplitDataCodec` 的 `Close` 原仅置空 `ss["Codec"]` 而不 `Dispose`（段链池缓冲无人归还）→ 统一改为“先归还再置空”。
- **B. `WebSocketMessage.Read` 链式零拷贝**：去除 `SpanReader(pk)` 整帧物化；改为索引直读头部（大端手拼）、掩码先读后切（切片会立即归还其前的段窗口）、负载 `pk.Slice(offset, len, true)` 沿链零拷贝转移所有权、掩码逐段 XOR（跨段连续）、Close 状态码/描述链式解析。
- **C. `LengthFieldCodec` 变长字段有界前缀读取**：`Size==0` 时原 `SpanReader(frame)` 会物化整个链式大帧，改为仅取 `Offset+5` 字节前缀（7 位压缩整数最多 5 字节）；新增 60KB 跨轮变长集成用例 `LengthFieldCodec_VarLength_BigPayload_Chained`。
- **D. `MatchResponse` 未命中立即归还**：新增 `Deliver` 本地函数，命中则所有权转移；未命中（无等待方）立即归还（池化消息回池、负载归还），消除无等待方应答的池缓冲无人释放；新增 `UnmatchedReplyTests`（256B/60KB × 用户负载/消息 4 组合）。
- 验证：net8.0 / net9.0 / net10.0 / net10.0-windows 全量套件：2671~2680 通过 / 12 跳过 / 共 1 失败（仍为 `CompositeConfigProviderTests.Test1` 环境性）。

### 第三轮（同日续）：关闭路径与写侧链式补齐

- **E. `HttpSession`/`WebSocket` 实现 `IDisposable`**：Http 通道（无认领 `e`）的粘包编码器原无归还点（半帧缓存连接断开后池缓冲无人释放）；现由 `HttpSession.Dispose`（`NetSession.Dispose` 会 `Handler.TryDispose`，主动/被动断开均触发）→ `WebSocket.Dispose` 归还；集成用例 `07-半帧断开：连接重置后编码器缓冲归还且服务可用`。
- **G. `WebSocketMessage.ToPacket` 掩码 XOR 逐段化**：原仅遍历首段（`body.GetSpan()`），链式负载掩码发送会越界；改为逐段遍历（掩码跨段连续，与读侧对称）；用例 `ToPacket_ChainedPayload`（掩码/非掩码 × 20KB 跨段）。
- **H. 客户端帧自动掩码（RFC 6455 §5.3）**：`WebSocketCodec.Write` 对 `WebSocketClient` 会话自动补 `MaskKey`（已显式设置的不覆盖；服务端方向禁止掩码）；用例 `08-60KB二进制（掩码+跨段链式）SHA256完整性`——真实网络上贯通“客户端掩码 + 服务端逐段 XOR 解码 + 跨轮组链”。
- 经查不改：`SessionBase.Close→CloseAsync→Pipeline.Close` 覆盖被动断开（Dispose 亦触发）；`DefaultMatchQueue.Clear` 已取消挂起等待方；`ReceiveAsync` 返回拥有包（所有权随切片转移）；`CheckCache` 超限归还完整；`StandardCodec` 的 `Read==false` 分支为死代码（`DefaultMessage.Read` 只抛异常或成功），未加无意义改动；`PayloadExtensions.TryGetMemory` 首段语义为公开文档化契约，保持不变。
