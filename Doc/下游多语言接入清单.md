# 下游多语言接入清单

适用于 NewLife.* 组件库与应用。目标：用最少步骤复用 NewLife.Core 的多语言能力，并让 README、徽章与 CI 与 Core 保持一致。

## 0. 语言口径

| 层面 | 建议 | 说明 |
|---|---|---|
| README | **11 种** | 中文、繁體中文、English、Español、Deutsch、日本語、Français、Português、Русский、한국어、العربية |
| 运行时词表（重要组件） | **31 种** | NuGet 下载量 ≥ 约 10 万次的组件，与 Core 词表集完全对齐 |
| 运行时词表（次要组件） | **11 种** | 与 README 读者一致；语言代码用 `zh-Hans`/`zh-Hant` |
| 兜底 | 英文源文 | 未提供的语言自动回退英文，缺译文不需要改代码 |

> 分层依据 **NuGet 下载量**：下载量 ≥ 约 10 万次的组件维护 31 种运行时词表（Redis、XCode、Stardust、Remoting、Cube、Agent、MQTT、RocketMQ），其余组件维护 11 种（Audio、Holiday、IP、Map、MySql、NoDb、NovaDb、Office、Video、XCoder、AntJob、GitCandy）。新增组件先按 11 种接入，下载量上来后再补齐 31 种。
>
> 各仓分层状态见该仓 `Doc/多语言本地化.md`，README 的 `locales` 徽章数字即运行时词表语言数。

## 1. 升级 Core

```bash
dotnet add package NewLife.Core
```

- 源生成器随主包以 `analyzers/dotnet/cs` 分发，**不需要额外引用生成器包**。
- 最低工具链：Visual Studio 2022 17.8+ / .NET SDK 8+（源生成器基于 Roslyn 4.8）。
- 升级后运行时消息以英文为源文；已翻译词条在 `zh-*` 环境自动显示中文，未翻译词条回退英文。升级须知见 Core 仓 `ChangeLog.md`。

## 2. 声明语言文件

在组件项目下新建 `Locales/zh-Hans.yml`、`Locales/zh-Hant.yml`，格式与 Core 相同：

```yaml
"Session {0} is closed.": "会话 {0} 已关闭。"
"Ready.": "准备就绪。"
```

- 键必须是**英文原文**，与代码中的模板逐字一致。
- 占位符集合与格式说明符必须与英文一致，否则编译失败或告警（LOC003/LOC004）。
- 英文是源文与兜底，**不需要 `en.yml`**。
- 新增**已登记词表键**必须同步补进全部语言文件；代码中新增的运行时词条（`L.T`、日志模板、`XException` 模板等）可先不入表，运行时回退英文。缺失翻译不报错。

若项目未启用自动挂载，在 csproj 显式声明：

```xml
<ItemGroup>
  <AdditionalFiles Include="Locales\*.yml" />
</ItemGroup>
```

> 用 `PackageReference` 引用主包时，包内 `build/NewLife.Core.props` 已把 `Locales/*.yml` 自动挂成 `AdditionalFiles`，通常**不需要改 csproj**。若项目里的 `Locales` 目录另有用途，加 `<AdditionalFiles Remove="Locales\*.yml" />` 取消自动挂载。
>
> 使用 `ProjectReference` 直连 Core 源码时，分析器不会随项目引用传递，需额外挂载：
>
> ```xml
> <ProjectReference Include="..\NewLife.Core\NewLife.Core.SourceGenerator\NewLife.Core.SourceGenerator.csproj"
>                   OutputItemType="Analyzer" ReferenceOutputAssembly="false" />
> ```

## 3. 盘点并英文化运行时消息

先盘点，不要一上来手工搜：

```powershell
# 列出中文运行时消息
pwsh -File check-english-exceptions.ps1 -Root . -Dir src -List

# 导出 CSV，交给翻译/批量处理
pwsh -File check-english-exceptions.ps1 -Root . -Dir src -Csv english-hits.csv
```

把消息改成英文源文：

```csharp
// 自定义异常：构造器自动翻译
throw new XException("Session {0} is closed.", sessionId);

// BCL 异常：显式翻译
throw new InvalidOperationException(L.T("Session {0} is closed.", sessionId));

// 日志：Logger.Format 自动翻译
XTrace.WriteLine("Session {0} is closed.", sessionId);
```

- **不要用字符串插值**（`$"..."`）：模板已经展开，无法再查表。
- 带实例前缀的日志封装：使用 `Log?.InfoPrefixed(prefix, format, args)` / `Log?.ErrorPrefixed(...)` / `Log?.WritePrefixed(level, ...)`，扩展内部先翻译并格式化原始模板，再拼前缀；不要把 `prefix + format` 整串交给 `L.T` 或 `Logger.Format` 查表。需要自行组装消息时，可用 `Logger.FormatMessage(Log, format, args)`。
- `[Description]`、`[DisplayName]`、`[Obsolete]` 等特性文本与 XML 注释不纳入词表。
- 自定义 Logger 重写 `Format` 时调用 `Localization.TranslateForLog(format, args)`。

## 4. 校验词表

```powershell
pwsh -File check-locales.ps1 -LocaleDir src\Lib\Locales -Baseline zh-Hans.yml -SourceDir src\Lib
```

校验内容：键集合一致、占位符一致、格式说明符一致、无孤儿键。孤儿键扫描可加 `-SkipOrphan` 关闭。

## 5. 写最小验证

```csharp
Localization.Culture = new CultureInfo("zh-CN");
Assert.Equal("会话 7 已关闭。", Localization.Translate("Session {0} is closed.", 7));

// 未注册语言回退英文
Localization.Culture = new CultureInfo("sw-KE");
Assert.Equal("Session 7 is closed.", Localization.Translate("Session {0} is closed.", 7));
```

- `Localization.Culture` 是进程级全局状态，改写它的测试应放入串行集合。
- `InvariantGlobalization=true` 下具名区域性不可用，只断言英文回退。

## 6. README 多语种

从 Core 仓根目录复制以下文件到下游仓根目录：

- `readme-languages.json`（改成自己的语言与文件名）
- `readme-package.json`（仓库地址、分支、包 README 源/目标）
- `sync-readme-languages.ps1`
- `sync-readme-package.ps1`
- `sync-readme-metrics.ps1` + `readme-metrics.json`（如果 README 里有会变的数字）
- `.github/workflows/readme.yml`（路径过滤器按需调整）

约定：

- English 用 `README.md`（默认落地页），简体中文用 `README.zh-CN.md`，繁體中文用 `README.zh-TW.md`，其余用 `README.<culture>.md`；不要再用 `Readme.MD` 或 `README.en.md`。
- English 与简体中文为双权威，内容变更同批更新；冲突时以英文为对外口径。
- 语言切换行由脚本生成，不要手改。
- 除 English 外的每份翻译开头写明"本翻译可能滞后，以 [English README](README.md) 为准"。
- `PackageReadmeFile` 指向生成的 `README.nuget.md`，不要把 `README.md` 直接打进包；生成物禁止手改。
- 运行 `pwsh -File sync-readme-languages.ps1 -Check` 与 `pwsh -File sync-readme-package.ps1 -Check` 确认。

## 7. 徽章

模板与规则见 Core 仓 `Doc/README多语言规范.md` 的"徽章模板（下游复用）"。

- 必选：License、NuGet 下载量、NuGet 版本、预发布版本、构建/测试、TFM、平台、贡献者。
- 可选：locales 数量、AOT 冒烟。
- **没有对应工作流就不要抄 AOT 徽章**。
- 静态数字徽章必须配同步脚本 + CI 校验；能用动态 GitHub Actions 徽章的优先用动态。

## 8. CI 门禁

```yaml
- name: Check English messages
  shell: pwsh
  run: pwsh -File ./check-english-exceptions.ps1 -Dir src

- name: Check locales
  shell: pwsh
  run: pwsh -File ./check-locales.ps1 -LocaleDir src/Lib/Locales -SourceDir src/Lib

- name: Check README languages
  shell: pwsh
  run: pwsh -File ./sync-readme-languages.ps1 -Check

- name: Check README metrics
  shell: pwsh
  run: pwsh -File ./sync-readme-metrics.ps1 -Check
```

## 9. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 编译后没有生成语言表 | `Locales/*.yml` 未声明为 `AdditionalFiles` | 加 ItemGroup，或确认包自动挂载生效 |
| LOC001 | yml 行格式错误 | 按 `"key": "value"` 修正 |
| LOC002 | 同文件键重复 | 删除重复行 |
| LOC003 | 占位符与英文不一致 | 让 `{0}`/`{1}` 集合一致 |
| LOC004 | 格式说明符不一致 | 保持 `:n0` 等与英文一致 |
| 词表有译文但运行时仍是英文 | 语言文件不在名为 `Locales` 的目录，或语言代码不匹配 | 检查目录名与 BCP 47 语言代码 |
| 类库改名 Core 文案不生效 | 类库默认 `overwrite: false` | 设 `<NewLifeLocalizationOverwrite>true</NewLifeLocalizationOverwrite>` |
| `L` 找不到或冲突 | 组件自己定义了 `NewLife.L`，或用了 `ProjectReference` 未挂分析器 | 删掉自定义 `L`，或显式挂 Analyzer |
| 测试在 CI 变红 | CI 的 `CurrentUICulture` 常为 en/invariant | 显式设置 `Localization.Culture` 或改断言 |
| 包消费验证命中旧缓存 | 同版本 nupkg 已被 NuGet 全局缓存 | 用唯一版本号打包（Core 的 `check-package-consumer.ps1` 已这样做） |

## 10. 推荐推进顺序

1. 先选一个消息多、下游依赖广的仓试点（建议 `NewLife.Remoting`）。
2. 试点同时覆盖：31 种运行时词表、11 种 README、CI 门禁、徽章。
3. 试点通过后，其余仓按本清单批量跟进；每仓一次提交，便于回滚。
4. 按第 0 节的下载量分层决定该仓维护 31 种还是 11 种；新增语言只需补词表文件，不改代码。
